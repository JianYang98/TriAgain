# 문서류만 바뀐 PR은 CI를 건너뛴다

> 2026-11-25. 사용자 승인.

[TIER 판정] Tier: 2 | 근거: `on.pull_request`만 변경, 배포 잡·push 트리거 무변경 | 판정자: 사용자 확정 | 2026-11-25

## 왜

- 문서류만 바꾼 PR도 `ci` → `e2e`가 약 6.5분 돌았다 (run 45320148033).
- 2026-11-25 GitHub API 기준 `main`·`develop`에 브랜치 보호·required check가 0건이다.

## 결정

`deploy.yml`의 `on.pull_request`에 `paths-ignore`를 둔다.
아래 파일만 바꾼 PR은 `ci`·`e2e`를 건너뛰고, 코드가 하나라도 섞이면 그대로 실행한다.

`*.md` · `docs/**` · `load-test/**` · `.claude/**` · `.agents/**` · `.gitignore`

일부러 뺀 것:

- `scripts/`: `CrewJoinRedisScriptTest`가 `scripts/crew-join-redis.sh`를 실행한다.
- `.github/`: 워크플로 변경은 검증이 필요하다.
- `lambda/`·`.editorconfig`·`.git-blame-ignore-revs`: 필요해지면 추가한다.
- `**.md`가 아니라 `*.md`인 이유: `src/` 아래 `.md`까지 무시하지 않으려고.

job 단위 조건 대신 `paths-ignore`를 골랐다.
job 단위 조건 방식은 잡·권한·감지 실패 처리가 늘어 지금은 선택하지 않았다.

## 감수할 것

- 건너뛴 PR에는 체크가 뜨지 않는다.
- required check를 켜면 그런 PR은 Pending 상태로 막힌다 (GitHub 문서).

## 되돌림 신호

- 코드가 포함된 PR에 `CI (Unit + Cucumber)`가 뜨지 않는다.
- required check를 도입하기로 한다.
