> 자매편: `blog-http-req-failed-vs-checks-failed.md`, `블로그소재-2026-06-12-tier-정책-기원.md`

## 제목 후보

1. **"리팩토링을 했는데 프로덕션 코드는 한 줄도 안 바뀌었다"** (모순 훅 — 성공작 `http_req_failed vs checks_failed`와 같은 공식)
2. "런타임만 프로파일링하지 마라 — AI 협업 컨텍스트도 측정 대상이다"
3. "컨텍스트는 유한 리소스다: API 명세 2,441줄이 매 작업 20k 토큰을 먹고 있었다"

→ 메인 추천: **1번** (호기심 훅) + 부제로 3번.

## 훅

- 부하테스트 때 나는 CPU·레이턴시를 측정해서 락 전략을 바꿨다. 그 눈으로 **내 개발 워크플로우 자체**를 봤더니, AI랑 페어프로그래밍할 때마다 API 명세 문서 한 개(2,441줄)를 통째로 로딩하고 있었다.
- 엔드포인트 **하나** 고치는데 명세 **전체**를 읽는다 — 런타임으로 치면 "메뉴판 한 줄 보려고 매번 책 전체를 메모리에 올리는" 셈.
- 그래서 리팩토링했다. **프로덕션 코드는 0줄 변경.** 바꾼 건 "AI가 일하는 방식(하네스)"이다.

## 핵심 주장 (한 줄)

> LLM 에이전트의 **컨텍스트(토큰)는 유한 리소스**다. 런타임 성능을 프로파일링하듯, 협업 컨텍스트도 관측·측정·최적화 대상이다.

## 구조 초안

1. **도입 — 모순**: "리팩토링했는데 프로덕션 코드 0줄." 무엇을 바꿨나?
2. **관측**: CLAUDE.md가 "작업 전 api-spec.md 읽어라"고 지시 → 매 작업 전량 로딩. 문제 인지.
3. **측정**: `wc -l` = 2,441줄 / ~70KB / 로딩 시 **~20k 토큰**. 나머지 spec 문서 전부를 합친 것보다 큼. (표로 제시)
4. **오해 정정**: 사실 자동 로딩은 아니었다 — "필요할 때" 읽히지만, 그 "필요할 때"가 엔드포인트 1개 작업에도 발생. 진짜 비용 경로를 정확히 짚는 게 최적화의 시작.
5. **처방 — 축이 중요**: 그냥 반으로 자르지 않았다. **바운디드 컨텍스트**(auth-user / crew / verification / notification / habit / internal)로 분할 + 라우터 인덱스 1장. DDD 사고를 문서 구조에 적용.
6. **검증 — 무손실**: 라인범위 슬라이싱으로 콘텐츠 이동, `###` 헤더 대조로 **엔드포인트 45개 100% 보존** 자동 검증. (부하테스트에서 `checks_failed`로 서버 건강성 검증했듯, 여기선 헤더 대조로 무손실 검증)
7. **여파 관리**: 문서만 바꾸면 끝이 아니다 — 스킬/커맨드/컨벤션의 참조를 갱신해야 정본 체계가 안 깨짐. 근데 수십 개를 다 고치면 그것도 리스크 → **라우터 인덱스가 stale 참조를 흡수**하게 설계해서 실제 편집은 8곳으로 최소화.
8. **결론 — 방법론의 전이**: 대상만 바뀌었다. CPU→토큰, p95→로딩량, 락 전환→도메인 분할, checks_failed→헤더 대조. **관측→측정→최적화→검증**은 런타임 밖에서도 똑같이 돈다.

- Claude Code / Cursor 등 **AI 에이전트로 실제 개발하는** 백엔드/풀스택 개발자

- 성능 엔지니어링 마인드셋을 **런타임 밖**으로 확장하는 데 관심 있는 사람

## 차별화 포인트 (왜 이 글이 먹히나)

- 대부분 "AI 잘 쓰는 법" 글은 프롬프트 팁. 이 글은 **AI 협업 시스템을 엔지니어링 대상으로 취급**하는 한 단계 위 층위.
- 성능 계열 자매편(`http_req_failed vs checks_failed`)과 **같은 방법론, 다른 리소스** → "이 사람은 어디서든 측정한다"는 일관성 서사.

## ⚠️ 안 팔리는 각도 (회피)

- "마크다운 파일 쪼갠 썰"로 열면 즉사. **반드시 측정 수치(20k 토큰 / 5×↓)와 "왜(유한 컨텍스트 예산)"를 먼저** 꺼낸다.
- "AI가 이만큼 편해졌어요" 감상문 금지. 관측→측정→검증의 **엔지니어링 규율**로 민다.
- 규모 자랑 금지 — 헤드라인은 성과 크기가 아니라 **방법론의 전이**.
