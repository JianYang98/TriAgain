## 9. 분석 〔분석〕

1. **이번 세션 최대 성과 = 유령 409의 등식 마감.** C10에서 "k6 409 < 서버 CR002" 4건이 관측만 되고 메커니즘 미확정이었는데, A4에서 재현(1건)되며 `EstabResets Δ+1`과 정확히 대응 — **수립·처리 완료 후 응답 유실(RST)**로 확정. 드롭 회계가 "AttemptFails + EstabResets" 2항 등식으로 완성돼, 8세션 연속 "드롭 = 수립층·락 무관" 결론이 앱 처리분까지 커버하는 완전 회계가 됐다.
2. **발현형(지연흡수 vs 드롭)은 락 전략·backlog로 결정되지 않으며, 제1 후보는 클라이언트 네트워크다.** A3↔A4가 같은 날·같은 backlog·같은 전략으로 정반대 발현인데, 유일하게 확인된 조건 차이가 **카페↔집 와이파이** 👤 — 07-04의 3점 용량-반응(RTT 41→드롭0 · 25→vu500 · 12→vu300)과 같은 축의 4번째 데이터점이다. 카페 경로의 혼잡·손실은 (a) 재전송·ACK 지연으로 accept 큐 역류(Overflow 1,443·257/256)와 지연흡수형 발현, (b) 완료 p95 팽창(k6 waiting에 경로 지연 포함) 양쪽을 한 번에 설명한다 〔추정〕. 서버 드레인 속도(앱/DB 상태) 기여분이 겹쳐 있을 수 있어 인과 확정은 아니나, "네트워크 이슈가 의심돼 재측정했다"는 운영자 판단 👤과 관측이 정합.
3. **vu400 드롭 17 < vu300 37 비단조**는 acceptQ 87/256 포착과 동행 — 그 런에서 accept 큐가 순간 완충 역할을 해 쿠키 실패분을 줄였을 가능성 〔추정〕. SynRetrans(193~208)가 vu300·400에서 드롭 대비 큰 것도 재시도 흡수 경로가 살아 있었음을 시사.
4. **완료 p95 세션 변동성이 전략 신호를 덮는다.** 같은 조건부가 A2(느림)→A3(최저속)→A4(시리즈 최속)로 하루 안에서 2배 이상 출렁였다 — 단 A3의 최저속은 카페 네트워크 👤가 유력 원인으로 분리되고(§9.2), 남는 순수 퍼즐은 A2(새벽, 네트워크 조건 미기록)의 열세다 — A2 결과서 §9.3의 "세션 상태 변수"(RDS 크레딧 등 👤 미확인)는 그쪽에만 걸린다. A4 최속은 acquire도 최저(294 < A1 338 < A2 383)인 점에서 **DB 왕복 자체가 빨랐던 세션**으로 읽힌다 〔추정〕 — 조건부의 병목이 풀이 아니라 DB 원자 UPDATE 왕복이라는 A2 §9.3 가설과 정합. **단일 세션 비교로 전략 우열을 갱신하지 않는다는 규약 재확인 — 07-04 A1↔C7 통제쌍이 여전히 정본.** A4의 최속 기록은 "조건부의 상한 성능" 관측치로만 등재.
5. **vu500 완료 p95(1,033) < vu400(1,283) 역전은 도달수 회계와 정합**: 도달(=완료요청) 310 vs 383 — 드롭이 유효 부하를 깎아 생존자 지연이 낮아지는 패턴 (C10 §8-2와 동형). A3↔A4의 p95 비교도 vu300 이상 구간은 이 이유로 무효 (도달수 다름).
6. **캐비앗**: (a) A4 전략 직접 증빙(기동 명령)은 미기록 — 단 acquire 지문(§7.2.1)이 간접 확정 (A2와 동일한 증빙 수준 도달), (b) vu20 콜드 오염 (기동 3분 후), (c) 기저 RTT 세션 내 가변(55→12ms)으로 RTT 축 해석 부적합, (d) A3 비교는 A3 결과서 부재 + **클라 네트워크 상이(카페↔집 👤)** 상태의 헤드라인 대조 — 통제쌍 아님, (e) EstabResets 세션 전체 Δ2 중 1건은 런 창 밖 — 분석서 §9가 **20:47:50**(vu500↔vu700 유휴 구간)으로 특정, `TCPAbortOnClose +1` 동반 = 배경 잡음 유력이나 소켓 단위 확정 불가.
