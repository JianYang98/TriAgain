### 4.2 acceptQ>0 순간의 전후 맥락 + SYN-RECV census 〔측정·ss, 신규〕

**vu400 (20:46:33~20:46:36, 서브초 원본)**

```
20:46:33 acceptQ=0/256 ESTAB=1
20:46:34 acceptQ=0/256 ESTAB=1
20:46:34 acceptQ=87/256 SYN-RECV=17 ESTAB=384   ← acceptQ 피크 순간
20:46:34 acceptQ=0/256  SYN-RECV=17 ESTAB=384
20:46:35 acceptQ=0/256  SYN-RECV=17 ESTAB=384   ← SYN-RECV=17로 2초간 고정
20:46:35 acceptQ=0/256  SYN-RECV=17 ESTAB=384
20:46:35 acceptQ=0/256  ESTAB=384               ← SYN-RECV 소멸(=17건 리셋)
```

**vu700 (20:49:01~20:49:04, 서브초 원본)**

```
20:49:01 acceptQ=0/256  ESTAB=1
20:49:01 acceptQ=0/256  SYN-RECV=257 ESTAB=1    ← SYN-RECV 257 최초 관측 (backlog+1과 동일 수치)
20:49:02 acceptQ=14/256 SYN-RECV=257 ESTAB=358  ← acceptQ 피크 순간
20:49:02 acceptQ=0/256  SYN-RECV=228 ESTAB=472  ← ESTAB이 472로 도약, SYN-RECV는 228로 하락
20:49:02 acceptQ=0/256  SYN-RECV=228 ESTAB=472
20:49:03 acceptQ=0/256  SYN-RECV=117 ESTAB=472
20:49:03 acceptQ=0/256  SYN-RECV=8   ESTAB=472
20:49:03 acceptQ=0/256  SYN-RECV=6   ESTAB=472
20:49:03 acceptQ=0/256  SYN-RECV=6   ESTAB=14 LAST-ACK=8
```

- **신규 발견 — SYN-RECV(ss 반개방 소켓 카운트)가 AttemptFails/드롭 수와 정확히 일치한다.** vu400: SYN-RECV 고정값 **17** = drop(17) = AttemptFails Δ(17). vu500(§3.1 창 내 원본에서 `SYN-RECV=190`, 3샘플 연속) = drop(190) = AttemptFails 190. vu700: SYN-RECV가 257(최초 관측)에서 228로 내려앉는데, **228 = AttemptFails Δ(228)과 정확히 일치**(드롭 229와는 유령 409분 1건 차이, §3의 등식과 정합). vu300은 창 내 첫 샘플 42(§0 인용, 과도기 값) → 안정값 37 = drop(37).
  - 즉 ss의 SYN-RECV는 "이번 초에 반개방 상태로 대기 중인 소켓 수"의 실시간 스냅샷인데, 그 가운데 살아남지 못하고 리셋될 집단의 크기가 드롭 등식과 **완전히 동일한 수로 관측된다** — nstat 카운터(사후 집계)와 무관한 독립 채널(ss 실시간 스냅샷)로 드롭 등식이 한 번 더 검증됨. 시리즈 최초로 ss가 "몇 개가 죽을지"를 소켓 상태만으로 사전에 드러낸 사례.
  - vu700의 최초 관측값 257은 backlog(256)+1과 수치가 같지만, 이는 acceptQ(별도 카운터, 완전히 다른 큐)가 아니라 SYN-RECV(반개방 소켓 상태) 수이므로 **backlog 실효값과 우연히 같은 숫자일 뿐 같은 지표가 아니다** — A3의 "257/256 오버플로"(acceptQ 큐)와 혼동 금지.
- acceptQ>0 두 표본(87/256, 14/256)은 모두 SYN-RECV가 아직 높고 ESTAB이 막 도약하는 과도기 한 샘플에만 나타났다가 다음 샘플에서 즉시 0으로 복귀 — 큐가 순간적으로 쌓였다 바로 드레인된 것으로, ListenOverflows Δ0(§2)과 모순되지 않는다(오버플로 임계 256을 넘지 않았음).

## 11. 〔분석〕 층 분리 결론 (측정값 아님)

1. **드롭 등식이 "AttemptFails + EstabResets" 2항으로 확장 마감된 것을 본 문서의 초단위·서브초 데이터가 뒷받침한다.** vu700 창의 EstabResets+1은 SyncookiesFailed 최대 버스트와 같은 1초 버킷에 나타났지만(§3.1), 이는 시간적 동시성일 뿐 인과관계 증거는 아니다 — "수립 완료 후 RST"라는 결과서의 해석은 CR002(+1)·ESTAB 공식 무결·SYN-RECV 채널(§4.2)까지 포함해 6중 관측으로 뒷받침되지만, 어떤 개별 소켓이 유령 409를 만들었는지 패킷 레벨 증거는 없다(로그 3종의 한계).
2. **SYN-RECV(ss) census는 이번 세션에서 새로 발견된 독립 검증 채널이다.** nstat(사후 누적 카운터)과 무관하게, ss의 실시간 반개방 소켓 스냅샷이 드롭/AttemptFails 수와 정확히 일치하는 값을 매 드롭 런마다 보여준다(§4.2). 향후 세션에서 SYN-RECV를 표준 관측 항목으로 승격할 가치가 있다.
3. **accept 큐 층은 이번에도 3중 침묵**(ListenOverflows 0 + ListenDrops 0 + BacklogDrop 0)이나, acceptQ>0 순간이 2회(87/256, 14/256) 실측된 것은 A2(0건)보다 진전된 관측이다 — 큐가 "쓰이되 넘치지 않는" 경계 거동을 포착했다.
4. **앱/락 무결 재확인**: 부하 구간 ERROR 0·Hikari/Tomcat/GC 로그 0·CR002 회계 마감(유령 409 1건 포함). 드롭 순간 앱에 이상 신호 없음 — 드롭≠락 전략 결론과 계속 정합.
5. **결측·잡음 항목은 전부 부하와 무관함을 확인**: nstat 결측 5초 전부 유휴 구간(§8), EstabResets 창밖 1건은 A004 스트레이 요청과 마찬가지로 배경 잡음으로 추정되나 소켓 단위 확정은 불가(§9, §5.1).
