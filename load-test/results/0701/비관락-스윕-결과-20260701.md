## 3. 정합성 판정

판정식: `success==10 && full+conflict==vu−10 && dropped==0 && 5xx==0` (expSuccess=min(vu,10)=10, expFull=vu−10).

- **vu20~200**: 전부 **PASS**. success가 정확히 10(정원)으로 고정, 초과분은 100% 409 full로 흡수.
- **vu300 1·2차**: success=10·5xx=0은 OK이나 dropped≠0 → **FAIL**. 단 `full + dropped == vu−10`(1차 191+99=290, 2차 226+64=290) — **정원초과분이 409 대신 연결 리셋으로 샌 회계**. 실제 입장은 10명뿐, 정합성이 깨진 게 아님.
- k6 thresholds와 일치: `join_success==10`·`join_5xx==0`은 6런 모두 ok / `join_dropped==0`은 vu20~200 ok, vu300 1·2차 fail.

## 4. 핵심 인사이트

**① 정합성은 완벽하다 — 락이 제 일을 함.**
vu20~200 전 구간 success가 정확히 10명(정원)으로 고정되고 초과분은 100% 409로 거부됐다. 오버부킹/언더부킹 0, CR023 재시도 고갈 0건. 비관락이 정원 경합에서 락 경쟁으로 인한 실패 없이 동작.

**② vu300 FAIL은 락 결함이 아니라 t3.micro accept 큐(acceptCount 100) 오버플로 노이즈다.**
근거 4가지:
- (a) drop 회계가 정원초과분과 정확히 일치(`full+dropped=vu−10`) — 락이 잘못 입장시킨 게 아니라 거부 응답이 연결계층에서 샌 것.
- (b) 콘솔 로그상 **성공 201 요청의 p95는 182ms**(`{expected_response:true}` avg 146ms)인데 전체 http_req_duration p95는 785ms → **서버 처리 자체는 빠르고, 지연은 연결 큐 대기**.
- (c) `http_req_connecting` p95 87ms(avg 50.7ms)로 상승 = **accept-queue 포화 지문**(정상 부하면 connecting ~수 ms).
- (d) 과거 비관 vu300 drop 편차(06-19=0 · 06-23=99 · 오늘 99/64)로 **전략 무관 노이즈** 재확인.

**③ 한계는 정합성이 아니라 latency가 먼저 온다.**
p95 단조 증가 — 219.5(vu20) → 282.3(vu50) → 483.8(vu100) → **840.6ms(vu200, vu20 대비 ~4배)**. 정원 경합에서 락 직렬화 비용이 부하에 비례해 누적되는 전형. vu300 p95가 vu200보다 낮아 보이는 건 **개선이 아니라 가장 느렸을 64~99건이 드롭돼 latency 모수에서 빠진 착시**(vu300 1차 max 1064.1ms로 오히려 최고치 갱신). 실측 처리 한계는 vu200~300 사이.

## 5. 전략 비교에 쓸 때 (다음 단계용 가이드)

- **유효 비교 구간 = vu20~200** (drop=0 클린). 특히 현실 부하 **vu50~100**이 조건부 update(C)·낙관락(B)과 맞대보기 가장 공정.
- **vu300은 비교에서 제외**하거나 "인프라 큐 한계 · 락 무관"으로 주석. drop을 락 실패로 읽으면 비관락이 억울하게 손해.

## 6. 남은 검증 (👤 사용자 — DB 자격증명 필요)

k6 `join_success`는 **애플리케이션 응답** 기준이 정원과 일치함을 보였으나, **DB 실제 행수 기준 정원초과 0건**은 미확인. 측정 직후 또는 보존 데이터로 확인 권장:

```sql
SELECT id, current_members, max_members,
       (SELECT COUNT(*) FROM crew_members m WHERE m.crew_id = c.id) AS actual_rows
FROM crews c WHERE id = 'loadtest-rush-crew-1';
-- 기대: current_members == 10 == actual_rows, actual_rows <= max_members
```
