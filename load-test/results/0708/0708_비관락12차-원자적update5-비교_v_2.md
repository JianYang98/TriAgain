# C12(비관락 12차) ↔ A5(원자적 UPDATE 5차) 비교 — v_2 · 해석 (v_1 수치 기반)

## 0. 세 줄 요약

1. **조건부(원자적 UPDATE)가 비관락보다 빠르다 — 이번 페어에서 3채널 전부 같은 방향** 〔확실〕: 서버측 완료 p95 7/7 낮음(v_1 §3, −110~−247ms·1.3~2.6×), 클라측 완료 p95 6/6 낮음(§2), acquire p95 7/7 낮음(§5, 1.6~3.3×). 07-04 같은 밤 페어(A1↔C7)의 결론이 더 정밀한 채널(버킷)로 재현됐다.
2. **격차의 본체는 커넥션 풀 대기(acquire)** 〔유력〕: 비관락의 SELECT FOR UPDATE 직렬화가 락 보유 시간을 늘려 10-커넥션 풀의 대기로 전이되고, 그 크기(acquire p95 격차 53→176ms, 246→90ms 등)가 서버측 완료 격차와 규모·순서 모두 정합한다.
3. **드롭·커널층은 이번에도 전략과 무관** 〔확실〕: 개시 VU(300), 발현형(즉사 쿠키실패), 등식(AttemptFails 단독), 불변식(ISN 2종) 전부 동일(§6) — 갈린 건 앱 안쪽(락→풀) 뿐이다.

## 1. 전략 실차이 판정 — 왜 이번 페어가 시리즈에서 가장 강한 증거인가

**〔확실〕 조건부 우세.** 근거의 구조가 이전 세션들보다 좋다:

- **통제 조건이 시리즈 최강**: 같은 밤·같은 클라 IP·같은 커널 부팅·같은 backlog(256)·거의 같은 셔플 순서(v_1 §1). 다른 것은 전략(재기동)과 VU 세트뿐. 07-04 A1↔C7 페어(기존 정본)와 통제 수준은 대등하고, **관측 채널은 더 정밀**하다(양측 버킷 = decaying max 워터마크의 런별 귀속 문제를 원천 회피).
- **네트워크가 A5에 불리했는데도 이겼다**: connecting 기저가 A5에서 전 VU +3~+21ms 높았다(v_1 §7). 즉 클라측 완료 우세(§2)는 네트워크 덕이 아니라 네트워크 불리를 **뚫고** 나온 것이고, 네트워크를 아예 배제한 서버측 채널(§3)에서 격차가 더 크고 일관되게(7/7) 나타난다. "회선이 좋아서 빨랐다"는 대안 설명이 데이터로 기각된다 〔확실〕.
- **재현성**: 무드롭 완료 p95의 조건부 우세는 06-19 스윕, 07-04 A1↔C7(+180~334ms), 이번 C12↔A5(서버측 −110~−247ms)로 **독립 3회째 같은 방향**이다. develop 기본값을 CONDITIONAL로 채택한 결정(PR 기채택)이 재보강된다.

단서 〔추정〕: 양 세션 모두 전략의 파일 증빙이 없고(👤 구두 확정), RDS 상태 미통제(v_1 §8). 다만 acquire 지문(비관 사다리 vs 무사다리)이 라벨과 정합해 라벨 오류 가능성은 낮다.

## 2. 격차의 메커니즘 — acquire가 본체라는 읽기 〔유력〕

- 경로를 따라가면: 비관락은 `SELECT FOR UPDATE`로 크루 행을 잠근 채 트랜잭션을 진행 → 락 보유 시간이 길수록 뒤 요청의 **DB 커넥션 점유 시간**이 늘고, 풀(10개)이 바닥나면 **acquire 대기**가 쌓인다. 조건부는 원자적 UPDATE 1문으로 락 보유 창이 짧다.
- v_1 §5가 이 그림 그대로다: acquire avg 격차가 저VU에서도 3배대(vu50~200에서 3.15~3.42×), p95는 전 VU 1.55~3.31×. 그리고 서버측 완료 격차(§3 배율 1.33~2.59×)가 acquire 격차보다 항상 **작다** — 완료 시간 = 고정 처리비 + 풀 대기이므로, 풀 대기 격차가 고정비에 희석된 형태. 크기 관계가 모순 없다.
- 409 경로의 비대칭(§4: 409 격차 > 201 격차)도 같은 기전으로 읽힌다 〔유력〕: 409는 정원 소진 **후** 도착한 요청이라 앞 요청들의 락·풀 대기가 누적된 꼬리에서 처리된다. 직렬화가 심할수록(비관) 꼬리가 길어져 409에서 격차가 증폭된다. C11↔A4 재계산(07-08)에서 본 방향과 동일 — 2번째 재현.

## 3. vu200 수렴의 정체 — 클라측 동률은 네트워크가 만든 착시 〔유력〕

v_1에서 유일하게 "동률"로 보이는 지점이 vu200이다(§2 Δp95 −28.2, §4 201avg는 C12 우세 +12.8). 그런데 **서버측(§3)은 vu200에서도 A5가 명확히 빠르다**(p50 −53.4, p95 −117.1, 배율 1.79×).

- 읽기: 클라측 완료엔 네트워크 왕복·재전송 노이즈가 실리는데, vu200 창의 connecting 기저가 A5 +8.4ms(§7)에 k6 SYN 재전송(A5 vu200 41플로우, tcpdump서 §4)도 겹쳐 서버측 우세를 상쇄했다 〔유력〕. 네트워크 성분을 직접 분해할 채널은 없어 크기 단정은 못 하지만(〔추정〕), "vu200에서 전략이 수렴한다"는 결론은 서버측 채널이 기각한다.
- 교훈: **전략 비교의 1차 채널을 클라측에서 서버측 버킷으로 옮길 근거가 생겼다.** 클라측은 네트워크 창 상태에 따라 ±수십 ms가 흔들리는 걸 이번 페어가 실측으로 보여줬다.

## 4. 드롭·커널층 — "전략 무관" 그림의 완성도가 올라갔다 〔확실〕

- 개시 VU 300, 즉사 쿠키실패형, AttemptFails 단독 등식, ISN 2종 불변식, 무응답 SYN 0 — 전부 양 세션 동일(v_1 §6). 락 전략이 바뀌어도 커널층 거동이 그대로라는 것은 "드롭 = t3.micro 수립 천장, 전략 무관" 결론(07-04 종결)의 재확인이다.
- 세부 차이는 노이즈 범위로 읽힌다 〔유력〕: vu300 드롭 34→10은 기존 비관 시리즈 내 편차(10~100)보다 작고, vu500 168→191도 마찬가지. acceptQ 76/256 1표본(A5 vu700)은 vu700이 세션 최대 버스트라서 나온 것이지 전략 신호가 아니다(C12는 vu700 자체가 없다).
- SynFailed 잉여=이중 RST(35→84)가 두 세션에서 각각 오차 0으로 닫힌 것은, 이 등식 체계가 세션·전략을 가로질러 성립하는 **관측 프레임**이 됐다는 뜻이다 — 다음 세션부터는 어긋나는 순간이 곧 새 현상의 신호다.

## 5. 방법론적 의미 — 이 페어가 시리즈에 남긴 것

1. **양측 버킷 페어의 가치 실증**: 워터마크 이월 문제(셔플로 전면화)를 버킷이 대체했고(C12), raw 유실(A5 vu500·700)을 서버측 버킷이 보완해 vu500 비교를 복원했다(v_1 §3). "클라 raw + 서버 버킷" 이중 채널이 표준 구성으로 확정될 만하다.
2. **오태그 사건의 수확**: RUN_TAG 실수가 raw 2런을 지웠지만, 도달×2 매핑 → 터미널 직접 증빙 → 버킷 보완의 3단 복구가 작동했다. 재발 방지 가드(k6 init throw, 미커밋)까지 이어졌다.
3. **한계 3개는 남는다**: ①전략 파일 증빙 부재(양쪽 👤) — 기동명령 캡처를 표준 절차화해야 한다(C11만 있음). ②vu700 비교쌍 없음 — 다음 비관 세션에 vu700을 넣으면 스윕이 완성된다. ③vu400은 양쪽 다 교란(C12 3중·A5 2중)이라 이번에도 인용 금지 유지.

## 6. 남은 퍼즐과의 관계

- **A2 열세 퍼즐**: A5 무드롭 완료 p95(329/481/758 @50/100/200)는 A4(327/554/895)와 같은 "빠른 조건부" 급이다. 즉 조건부 4세션 중 A2(572/985/1588)만 이상치로 더 고립됐다 — RDS 드리프트 가설(새벽 4스윕째)이 상대적으로 강해졌지만 여전히 미확인 〔추정〕.
- **C10 개시 VU 후퇴 퍼즐**: 이번 페어는 둘 다 개시 300이라 새 정보 없음. accept-count 256↔512 재현실험이 여전히 유일한 마감 경로.
