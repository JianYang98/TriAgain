## 3. 사실 목록 〔측정·파생〕

1. **정합성(락)은 전 구간 완벽** — `success=10`(정원 정확) · `conflict=0` · `5xx=0`, 7/7런 예외 없음.
2. **409 = 1,184, 3채널 정확 일치** — k6 full 합계 = Micrometer(`status=409,error=none`) = **앱 로그 CR002 카운트**, 셋 다 1,184로 0오차. `409+IOException` 0건 = **드롭 세션 중 유령 409 미발생은 시리즈 최초**(C10·A4·C11은 각 1건).
3. **드롭은 vu300부터** (34/114/168) — **실행 순서와 무관**: vu200은 마지막(7번째)에 돌았어도 드롭 0, vu400은 2번째에 돌았어도 114. 드롭 개시 VU=300은 C11(40/126/213)과 같은 층. vu700 미측정이라 상한 미확인.
4. **실행 순서 셔플의 부작용/효용** — decaying max 워터마크가 인접 런으로 전면 이월되어(예: vu50 창 max 1,894.7 = 직전 vu400 잔상) **이번 세션 런별 acquire_max 귀속은 불가**. 대신 버킷 백분위(런 전후 델타)가 이를 구조적으로 대체 — `0708/prometheus/README.md` 하이라이트 표 참조.
5. **vu400은 3중 교란 이상치** — 완료 p95 **2,843.9**·avg 1,781.2·p50 2,028.8로 세션 내 압도적 최고. 단 ⚠️(a) **첫 Major GC 165ms가 런 정중앙**(23:58:25, minor 3회 동반), (b) 드롭 114로 세션 2위, (c) 세션 2번째 런(JVM 웜업 초기). **이 런의 절대값을 전략 비교에 인용 금지** — 교란 분리 불가.
6. **acquire 백분위 시리즈 최초 산출 세션** — percentiles-histogram(bdd2322) 첫 적용. 런별 p50/p95는 README 표 정본(피크 vu400: avg 224.4·p50 157.1·p95 765.0). acquire n=완료×2도 7/7 재확인.
7. **검증: success+full+dropped = 목표 VU, 7/7 정확** (예: vu500 → 10+322+168=500).
8. **완료 p95 ≥ 드롭포함 p95, 드롭 런 3/3** (vu300 1506.0>1498.7 등) — 드롭=빠른 죽음이 집계를 끌어내리는 방향 재확인(0707 비교문서 §7.4와 동일 기전).
