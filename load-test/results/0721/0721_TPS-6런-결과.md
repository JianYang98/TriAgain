## 3. 판정 (실행가이드 §10-6 4기준)

**① 목표 rate 유지**: 6런 전부 프로파일 완주 (달성 348.4~349.6/s ≈ 이론 평균 350/s, 500/s 유지 구간 포함).
드롭은 P/A 75·C/A 58·P/B 104건(≤0.17%) — **시험 범위(≤500/s)에서는 어느 전략도 도착률을 감당 못 하는 구간이 없었다.**
"한계 지점"은 500/s 밖에 있으며 이번 범위에서 미도달.

**② 성공 쓰기 TPS 꺾임**: 꺾임 없음. A는 3전략 동률 ~275 (차이 0.6% — 성공량은 전략이 아니라 워크로드가 결정).
B는 3전략 모두 구조 상한 `rate×10/K = 350×0.1 = 35.0`에 정확히 안착 (35.49~35.53) — §10-1 규칙의 실증.
**전략 우열은 처리량이 아니라 지연 꼬리와 포화 여유에서 갈렸다.**

**③ 지연·드롭 급증**: 급증(붕괴) 없음, 단 꼬리 순위는 A·B 모두 일관되게 **C < O < P**:
- p95: C 175.9/176.9 < O 208.6/181.7 < P 223.0/201.3
- p99: C 434.1/266.8 < O 502.7/350.0 < P 665.7/528.2
- 드롭·VU 증원·서버 포화(§2)도 P에만 집중: P/A는 Tomcat 200/200 만석 + Hikari 대기 189 순간 발생
  → 락 대기가 커넥션 점유 시간을 늘려 풀(10)이 깔때기가 되는 구조. O는 드롭 0(빠른 실패로 지연 분산 최소)이나 그 대가가 conflict.

**④ A↔B 특성 변화**:
- **P**: B에서도 거절(만석 확인)이 row 락을 경유 → 거절 트래픽까지 직렬화 (B에서 pending 56·busy 118 — O/C의 5~24와 대조). 오픈런에서 가장 불리한 구조.
- **O**: conflict가 A 301 → B 46으로 **감소** (역직관 — B는 대부분 만석 크루 타격이라 버전 경쟁 전에 도메인 검사로 거절, 경쟁은 창 초반 충원 순간에만). 단 A의 301건은 재시도 3회 소진 후 포기 = 실사용자 가입 실패 301건이라는 의미.
- **C**: 두 케이스 모두 꼬리 최단·서버 부담 최소. B에서 p99 266.8ms로 유일하게 300ms 미만.

**종합**: 처리량 동률 조건에서 **CONDITIONAL 우위** (지연 꼬리 최단 + 포화 여유 최대 + 실패 모드 없음),
OPTIMISTIC 중간 (드롭 0이지만 저경합에서 conflict로 실사용자 실패 발생), PESSIMISTIC 열위 (거절까지 락 경유로 꼬리·포화 최악).
— 기존 VU 시리즈의 C 채택 권장과 일관.
