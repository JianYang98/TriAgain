**vu300 `SyncookiesFailed +3` 무해 검증 — 증거 체인 5항**: 5차 vu700의 `Failed +7 = 드롭 7`(7관측 수렴)과 구조가 다름을 아래로 확정한다.

1. **시간 순서 (마이크로초 정본)**: vu300 raw JSON 스트림(`crew-rush-jian_C6_max10_vu300.json`, 300개 요청별 타임스탬프)의 **마지막 응답 수신 = 20:41:19.595063** (299건은 :16.49까지, 꼴찌 1건만 :19.59). 실패 발생은 **20:41:20.3~0.7** — nstat 서브초 샘플(~3회/초)에서 20:41:20의 첫 2샘플까지 `Failed=23` 유지, 3번째 샘플에서 26. → **300건 전원 응답 수신 완료 후 ~1초 뒤에 실패 발생** (완료시각 파일명 ±1s 추론이 아닌 원시 타임스탬프 확정).
2. **무영향**: raw 300 Point 전부 status 201(10)·409(290) — status 0(리셋) 없음. checks 1,200/1,200 · dropped 0 · ss ESTAB 피크 301=VU+1(결손 0).
3. **RST 쌍**: 동일 서브초 구간에서 `Failed 23→26` = `OutRsts 642→645` 동시 점프 — "검증 실패 → RST 발사" 3쌍이 커널 카운터에 그대로 대응.
4. **배경 노이즈 배제**: `SyncookiesFailed`는 6차 로그 6.5분 전체에서 **단 1회** 이동했고, 5차 종료값(23) = 6차 시작값(23) — **세션 사이 8h20m 배경 트래픽 동안 0건**. 8시간 침묵하던 카운터가 vu300 종료 1초 뒤에만 +3 → 무작위 배경 소행 기각.
5. **정황 (발생원)**: `SynRetrans +6`(:15~:19) = 중복 SYN-ACK→중복 ACK 발생원이 실재. 꼴찌 요청(:19.59 완료)이 곧 connecting 4,975ms 사다리 이상치(시작 :14.6 + ~5s = :19.6 정합) — 재전송 사다리를 탄 커넥션이 실패 직전까지 살아 있었음.

→ 확정 범위: "vu300 런과 연관된, 이미 볼일 끝난 패킷의 검증 실패이며 산 요청은 0건 피해". 패킷 신원(재전송발 중복 ACK인지)은 포트/시퀀스 정보가 어느 로그에도 없어 **tcpdump 없이는 확정 불가 — 기전 미확정·영향 0 유지**(비교서 §6 ※와 동일 판정).
