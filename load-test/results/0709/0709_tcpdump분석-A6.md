## 2. 드롭 플로우 추적 — 쿠키-드롭 메커니즘 〔측정〕

드롭 메커니즘은 **SYN 쿠키 검증 실패(ISN₂ 패턴)** — 커넥션 수립 층의 현상이며 락 전략과 무관하다.

### 쿠키-드롭 대표 플로우 (vu400, 2×Out RST 유형)

```
In  S   seq=1205335185
Out S.  seq=3593919312  (ISN₁)
In  S   (재전송, seq 동일)
Out S.  seq=3593919312  (ISN₁ 재전송)
In  S   (재전송2, seq 동일)
Out S.  seq=3123201850  (ISN₂ ≠ ISN₁)
Out R   seq=3593919313  (=ISN₁+1)
Out R   (이중)
Out S.  seq=3123201850  (ISN₂ 재전송, ~1s 후)
In  R   seq=1205335186  (=SYN+1, 데이터 0)
```

**불변식 (드롭플로우 전수 공통)**:
1. **SYN-ACK ISN이 정확히 2종** — 첫 SYN에 ISN₁, 재전송 SYN에 다른 ISN₂. ISN-2종 플로우 수는 드롭플로우 수와 대응(vu700만 −3, §3).
2. **Out RST seq = ISN₁ + 1** — 서버 RST는 항상 첫 SYN-ACK의 시퀀스 공간을 종료.
3. **종료는 클라 In R, seq = SYN + 1** (데이터 0) — 핸드셰이크가 완성되지 못한 채 종료됨을 뜻함. §3의 유령409(seq = SYN+385)와 대비되는 지점.

### 첫 RST 지연 (즉사형)

- 런별 첫 RST(min/mean/max, ms): vu300 92/**100**/105 · vu400 130/**180**/207 · vu500 156/**227**/1152 · vu700 298/**423**/489.
- 4런 mean이 100~423ms 범위 — **즉사형**(RTO 백오프 수 초 단위가 아니라 첫 재전송 직후 RST). vu500 max 1152ms 1건은 스트래글러.
- **무응답 SYN 0건** — 모든 클라 SYN이 최소 1개의 SYN-ACK을 수신. vu200: 47플로우가 SYN 재전송했으나 전량 완결(드롭 0).

## 3. 🔑 유령409(409+IOException) 3건 — 패킷 증거 〔측정·파생〕

- **k6 409 합 1,553 · 서버 CR002 로그 합 1,556 → 차이 3.** 서버 Micrometer: 409(error=none) 1,553 = k6 409와 일치, **409+IOException 3건**(전부 vu700, 첫 08:58:55Z) = `http_join_ioerror_raw` 최종 누계 3(정본, prometheus-a6).
- **패킷 레벨 독립 확증**: vu700 **드롭플로우 241 − ISN-2종(쿠키) 238 = 3**.
- 이 3건은 §2의 쿠키-드롭과 시퀀스가 다르다:
  - **단일 SYN-ACK ISN**(쿠키 아님, 정상 재전송 — ISN₂ 분기 없음)
  - **클라 RST seq = 첫 SYN seq + 385** — 클라가 약 384바이트의 HTTP 요청을 실제로 전송했다는 뜻(커넥션 수립 완료 + 데이터 도달). 서버가 요청을 획득·처리(409 응답)했으나 그 **응답이 클라에 도달하지 못함**.
  - 대비: 쿠키-드롭 238건은 **클라 RST seq = SYN + 1**(데이터 0 = 핸드셰이크 미완성).
- 3건 전부 vu700, 클라 RST 동일 시각 **17:58:52.305**.
- **락 정합성에는 무해**(success=10, 5xx=0 — 정원 초과 판정 자체는 정상 수행됨).
- **3채널 확증**: ① k6 409 − 서버 CR002 로그 차(3) ② Micrometer 409+IOException(3) ③ pcap "seq+385 데이터전송 드롭플로우"(3).

### 유령409 대표 플로우 (vu700, 포트 49888)

```
In  S   seq=425351710
Out S.  seq=1113953652  (ISN)
In  S   (재전송, seq 동일)
Out S.  seq=1113953652  (같은 ISN)
Out R   seq=1113953653  (=ISN+1)
In  R   seq=425352095   (=SYN+385, 데이터 전송 증거)
```

- ⚠️ ACK/PSH는 필터로 미포착되어 직접 관측되지 않지만, **클라 RST의 seq가 SYN+1이 아니라 SYN+385로 증분되어 있다는 사실 자체가 데이터 전송(HTTP 요청 송신)의 직접 증거**다.
- 409 정합: **k6 409 1,553 = Micrometer 409(none) 1,553**(2채널 일치). 서버 CR002 로그 1,556 = 1,553 + 유령409 3.

## 4. 이중/삼중 Out RST = 잉여 〔측정·파생〕

Out RST 패킷 총량은 드롭플로우 수보다 많다 — 일부 플로우에서 서버가 RST를 2회 이상 송신했기 때문이다.

| 런 | Out RST 1회 | 2회 | 3회 | 히스토그램 검산 | Out RST 총량 |
|---|---|---|---|---|---|
| vu300 | 31 | 0 | 0 | 31×1 = 31 | 31 |
| vu400 | 14 | 76 | 41 | 14×1 + 76×2 + 41×3 = 14+152+123 | 289 |
| vu500 | 81 | 153 | 0 | 81×1 + 153×2 = 81+306 | 387 |
| vu700 | 21 | 219 | 1 | 21×1 + 219×2 + 1×3 = 21+438+3 | 462 |

- **히스토그램 검산 4/4 정합** — Out RST 총량(289/387/462/31)이 1×/2×/3× 구성의 산술합과 정확히 일치.
- 이중·삼중 Out RST는 쿠키 SYN-ACK(ISN₂) 재전송과 클라 SYN 재전송이 겹치는 구간에서 서버가 RST를 반복 송신한 결과로 관측된다(§2 대표 플로우의 "Out R(이중)" 참고). nstat 채널이 없어 이 세션에서는 커널 카운터(SyncookiesFailed 등)와의 교차검증은 불가 — pcap 단독 관측.

## 8. 관측이 시사하는 것 / 확정하지 않는 것 〔분석 — 사실 아님〕

- 드롭 시퀀스(재전송 SYN에 다른 ISN₂ 응답 → ISN₁ 공간에 RST)는 SYN 쿠키 검증 실패 패턴과 형태가 일치하나, **ACK 패킷이 필터로 빠져 있어 핸드셰이크 완성 방향은 seq 증분만으로 추론**한 것이며 직접 확인은 아니다.
- **드롭 개시 VU = vu300의 원인 축**(실효 SYN큐 한도 / 클라넷 / 서버 상태) — 이 세션 채널로는 특정 불가. nstat 부재로 커널 카운터 대조도 불가능하다. vu300은 실행순 5번째(vu400·vu700 뒤)였음에도 드롭이 발생해, 실행 순서가 아니라 VU 수준이 드롭 개시를 결정한다는 점만 확인된다.
- **클라 SYN 재전송의 발생 원인**(간격·타임아웃 임계) — 이 캡처만으로 미확정.
- **유령409 3건의 정확한 발생 격자**는 vu700 창(prometheus 첫 관측 08:58:55Z)까지만 확인되며, 그 이상의 시간대별 세부 분포는 미확정.
- 이중/삼중 Out RST가 발생하는 정확한 커널 경로(재전송 타이밍과 RST 재발행의 인과) — nstat 부재로 미확정.
