## 0. 캡처 개요 〔측정〕

- 구간: **21:04:38 ~ 21:24:21 KST**, 총 **10,366패킷**. vu20(21:04:39 시작) 0.5초 여유로 포함 — 8런 전부 캡처 범위 안이다.
- JVM 단일 기동 21:03:33 KST, 런 중 재기동 없음 — 캡처 전체가 동일 인스턴스를 대상으로 한다.
- 실행순 셔플: vu20 → vu400 → vu700 → vu50 → vu300 → vu100 → vu200 → vu500.
- k6 success=10 정확 전 런, 5xx=0 — 락 정합성은 패킷 레벨과 별개로 완벽하다(완료/드롭 수치 정본은 이 세션 결과서).

|---|---|---|---|---|---|---|---|
| vu20(1)  | 0   | 0   | 0   | 0   | 0   | 0 | - |
| vu400(2) | 130 | 130 | 130 | 0   | 211 | 0 | 266 / 268 / 305 |
| vu700(3) | 176 | 332 | 176 | 156 | 525 | 0 | 352 / 337 / 464 |
| vu50(4)  | 0   | 0   | 0   | 0   | 0   | 0 | - |

- **무드롭 런 5개(20/50/100/200/300 중 300은 아래 참고)** — 정확히는 vu20/50/100/200이 In RST 0으로 완전 무드롭이고, **드롭 개시는 vu300**부터다(0/0/0/0/36/130/211/176 순).
- **vu200**만 예외적으로 reSYN포트 131건(클라 SYN 재전송)이 있었으나 드롭 0 — 재전송이 전량 지연흡수로 완결됐다.
- **무응답 SYN 0건** — 세션 전체에서 모든 클라 SYN이 최소 1개의 SYN-ACK을 받았다. "SYN 자체가 버려진" 플로우는 없다.
- 드롭 총합 = 36+130+211+176 = **553**.

## 2. 드롭 채널 불변식 〔측정〕

- **In RST(클라→서버) = k6 drop 8/8 정확** — vu300 36 · vu400 130 · vu700 176 · vu500 211, 나머지 런 0. 드롭 확정 채널.
- **ISN₂(서버 SYN-ACK ISN 2종+ 플로우) = drop 4/4 정확** — 36/130/176/211, In RST와 완전히 동수·동플로우. SYN쿠키 재생성 지문이다: 첫 SYN에 ISN₁ 응답, 재전송 SYN에 ISN₂(≠ISN₁) 응답이 붙는 플로우 수가 드롭 수와 정확히 일치한다.
- **Out RST(서버→클라) = nstat OutRsts 정확** — 36/130/332/366(vu300/400/700/500). 서버발 RST는 순수 win0(쿠키 검증 실패) 성격이다.
- **이중RST 잉여(서버가 한 플로우에 RST 2회, Out RST − In RST)**: vu700 = 332−176 = **156** · vu500 = 366−211 = **155** — nstat 잉여 정확과 일치. vu300/vu400은 Out RST = In RST(이중RST 0)으로, 고VU 두 런(700/500)에서만 서버가 같은 플로우에 RST를 반복 발사한다.
- **클라 RST seq offset = +1(쿠키드롭·데이터0) 100%** — 드롭 553건 전부 클라 In RST의 seq가 이전 서버 SYN-ACK ack 기준 +1로, 데이터 전송이 없는 상태에서의 순수 핸드셰이크 종료다. **+385(HTTP 데이터가 실린 흔적) 0건** — 즉 드롭 플로우 중 실제 요청 바디가 서버에 도달한 사례가 없다.
- **reSYN포트(클라 SYN 2회 이상)**: vu200=131인데 drop=0 — 재전송이 전부 지연흡수(무드롭)로 끝났다. vu300=200·vu400=211·vu700=525·vu500=386으로, reSYN 수는 드롭 수보다 항상 크다(재전송 중 일부만 최종 드롭으로 귀결).
- **무응답 SYN = 0 전 런** — 커널이 SYN 자체를 묵살한 사례는 없다(전량 최소 1개 SYN-ACK 응답).

## 3. 첫 서버 RST 지연 〔측정〕

드롭이 발생한 4개 런(vu300/400/700/500)의 "첫 클라 SYN → 첫 서버 RST" 지연:

| 런 | p50(ms) | mean(ms) | max(ms) |
|---|---|---|---|
| vu300 | 134 | 134 | 138 |
| vu400 | 266 | 268 | 305 |
| vu700 | 352 | 337 | 464 |
| vu500 | 254 | 259 | 1168 |

- vu300·vu400은 p50≈mean으로 분포가 좁다. vu700은 mean(337)이 p50(352)보다 낮아 짧은 쪽 꼬리가 존재한다.
- **vu500만 max(1168)가 mean(259)의 4배 이상** — 롱테일 1건이 존재한다(고VU 재전송 누적 영향으로 보이나 원인 특정은 §7에서 유보).
- 전 런에서 지연은 "즉시 드롭"이 아니라 최소 100ms 이상 SYN 재전송·쿠키 재생성을 거친 뒤 종료된다.

## 4. 409 채널 교차검증 & 유령409 〔측정·파생〕

| 채널 | 총합(8런 합) | 비고 |
|---|---|---|
| k6 409 (raw) | 1637 | 10+260+514+40+254+90+190+279 |
| 서버 CR002 grep | 1637 | CR002만 등장, 다른 CR코드 0 |
| Micrometer 409 | 1637 | per-run 10/260/514/40/254/90/190/279 정확 일치 |

- **3채널 정확 일치 1637 → 유령409 0건.**
- pcap 근거: 드롭 553건 전부 클라 RST seq offset이 **+1**(쿠키드롭·데이터0)이고 **+385(데이터 실린 유령409 패턴) 0건** — 즉 드롭 플로우에서 서버로 HTTP 요청 바디가 실제로 전달된 사례가 없으므로, "드롭으로 보였지만 사실은 서버가 처리해 409를 반환한" 유령 케이스가 패킷 레벨에서도 존재하지 않는다.
- 3채널 수치 일치 + pcap seq offset 100% 정합 → 이 세션은 유령409가 발생하지 않은 것으로 확정된다.

## 5. 채널 교차검증 매트릭스 〔파생〕

| 채널 | vu300 | vu400 | vu700 | vu500 | 비고 |
|---|---|---|---|---|---|
| k6 drop | 36 | 130 | 176 | 211 | — |
| nstat AttemptFails | 36 | 130 | 176 | 211 | ✓ |
| pcap In RST | 36 | 130 | 176 | 211 | ✓ |
| pcap ISN₂플로우 | 36 | 130 | 176 | 211 | ✓ |
| nstat OutRsts | 36 | 130 | 332 | 366 | =SyncookiesFailed |
| pcap Out RST | 36 | 130 | 332 | 366 | ✓ |
| 이중RST 잉여(Out−In) | 0 | 0 | 156 | 155 | nstat 잉여와 일치 |

- **드롭 4채널 오차 0**(k6·AttemptFails·In RST·ISN₂플로우) + **SynFailed 계열 2채널 일치**(OutRsts·pcap Out RST).
- nstat ListenOverflows=0 · ReqQFullDrop=0 전 런 — accept큐 오버플로/SYN큐 자체 드롭은 없고, 드롭은 전량 **SYN쿠키 검증 실패(즉사)형**이다.
- EstabResets는 vu50에서만 1(배경 노이즈, drop 0)이고 나머지 런은 0 — 드롭 등식(drop = AttemptFails 단독)이 성립한다.

## 6. 관측이 시사하는 것 / 확정하지 않는 것 〔분석 — 사실 아님〕

- 드롭 시퀀스(재전송 SYN에 ISN₂가 응답되고, 뒤이어 클라가 RST로 종료)는 nstat의 SyncookiesFailed 수치·시각과 동행하며, "SYN큐 재전송 → 쿠키 SYN-ACK 재생성 → 검증 실패 → RST" 해석과 모순되는 관측은 없다. 단, 이번 facts sheet에는 개별 패킷 시퀀스 타임라인(ISN 값 자체)이 실려 있지 않아 패킷 페이로드 수준의 재현은 이 문서에서 다루지 않는다. 확정 아님.
- **드롭 개시가 vu300부터인 이유**는 이 세션 채널만으로 실효 SYN큐 한도인지 클라 볼리인지 특정할 수 없다 — vu300에서 이미 In RST 36 · ISN₂ 36으로 확정 드롭이 존재한다는 사실까지만 확정한다(경계가 vu300 "직전"이 아니라 vu300부터라는 점은 C-시리즈 이전 세션들과 다를 수 있으나, 다른 세션과의 비교는 이 문서 범위 밖이다).
- **vu700·vu500의 이중RST(156/155)가 vu300·vu400에서는 0인 이유**는 서버 부하·재시도 타이밍 등으로 추정되나 패킷만으로 원인을 특정할 수 없다 — 관측된 규칙성(Out RST=nstat OutRsts 정확 일치, 이중RST=잉여 정확 일치)만 사실로 남긴다.
- **vu500 첫 RST 지연 max(1168ms)가 mean(259ms) 대비 이례적으로 큰 이유**는 이 캡처만으로 특정 불가 — 단일 롱테일 관측 사실만 남긴다.
- 전략 라벨(비관락 14차)은 지문 정합 + **👤 운영자 확정(2026-07-09)**. accept-count(256)는 ss 관측치로, Tomcat 설정값 자체는 👤 확인 대상.
