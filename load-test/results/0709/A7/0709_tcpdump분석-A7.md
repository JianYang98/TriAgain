## 3. Out RST 등식 & 이중RST 〔측정+파생〕

- **Out RST = nstat SyncookiesFailed, 3/3 정확 일치**: vu400 82 / vu700 374 / vu300 35.
- **vu700 잉여 133**(374−241) = **이중RST 실체** — SYN 재전송 플로우가 쿠키실패 RST를 반복 수신한 결과로 확인됨(reSYN 581플로우 중 일부가 재전송할 때마다 쿠키 재검증 실패 RST를 다시 받는 패턴).
- vu400·vu300은 Out RST = In RST(82=82, 35=35) — 잉여 0, 이중RST 없음. vu700에서만 관측.

## 4. ISN₂(쿠키 재생성) 지문 〔측정〕

서버 SYN-ACK ISN이 2종으로 관측되는 플로우 = syncookie 재생성 지문.

- **vu700 241 = 드롭 241 정확** / **vu300 35 = 드롭 35 정확**.
- **vu400 84 = 드롭 82 + 생존 2**(쿠키를 받고도 결국 수립에 성공한 2플로우).
- **vu20 2**(드롭 0인데 쿠키 2건 발생 — 전량 흡수, 생존).
- **vu200 0**(reSYN 85플로우 전부 동일 ISN 재전송 = 쿠키 미발동, 지연만으로 흡수).
- → **ISN₂ ⊇ 드롭** (근사 상한 채널이지 등식은 아님 — vu400·vu20에서 드롭보다 큰 값 확인).

## 8. 관측이 시사하는 것 / 확정하지 않는 것 〔분석 — 격리, 사실 아님〕

- **발현형 = 즉사 쿠키실패형**: 드롭은 전부 SYN큐 → syncookie 발급 → ACK 쿠키검증 실패 → RST 경로로 관측됨. accept큐 오버플로·backlog드롭 경로의 흔적은 이 pcap 채널에서 나타나지 않는다.
- **vu400 수치 인용 캐비앗**: vu400은 콜드 JVM 2번째 런(기동 3분 내) + 도달 318 최중부하가 겹치는 창이다. vu400의 플로우·ISN₂·이중RST 부재(잉여 0) 등을 다른 런과 단순 비교할 때는 이 겹침을 감안해야 한다.
- **vu200 대비 사례**: 같은 세션 안에서 SYN 재전송(85플로우)이 발생했음에도 쿠키 미발동·드롭 0으로 전량 흡수된 유일한 런 — 드롭 발생 여부가 재전송 발생 여부만으로 결정되지 않음을 시사한다(원인 축은 이 pcap 채널만으로 특정 불가).
- 드롭 개시 VU(vu300)의 원인 축(실효 SYN큐 한도/클라넷/서버 상태)은 이 pcap 채널 단독으로는 특정할 수 없다.
