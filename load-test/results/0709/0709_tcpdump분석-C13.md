## 0. 캡처 개요 & 필터 특성 〔측정〕

- 구간: 17:10:49 ~ 17:35:34 KST (첫/마지막 패킷). 총 **11,082패킷**(인터페이스 gif0 11,080 + lo0 2), 파싱 실패 0.
- **전 패킷 `length 0`, 플래그는 S / S. / R / R. 4종만** — 순수 ACK·PSH·FIN 0건. C12와 동일한 SYN·RST 계열 전용 필터 특성.
- k6 클라(220.116.188.182)↔서버 전체 플래그×방향: **In S(클라 SYN) 4,547 · Out S.(서버 SYN-ACK) 4,732 · In R(클라 RST) 594 · Out R(서버 RST) 1,046 · Out R.(서버 RST+ACK) 161**.

## 2. 드롭 플로우 전수 추적 〔측정〕

드롭 3런 합계 594(141+257+196) = k6 총드롭 594 = pcap In RST 594, 런별(141/257/196)까지 전부 정확 일치. **드롭플로우 = In RST = ISN-2종 플로우** 3중 일치(각 드롭플로우당 In RST 정확히 1개).

**불변식 3개 (드롭플로우 594/594 공통):**
1. SYN-ACK ISN이 정확히 2종 — 첫 SYN에 ISN₁, 재전송 SYN에 다른 ISN₂가 응답됐다.
2. Out RST seq = ISN₁+1 — 서버 RST는 항상 첫 번째 SYN-ACK의 시퀀스 공간을 종료한다.
3. 종료는 서버의 ISN₂ SYN-ACK 재전송에 대한 클라 In R.

## 3. 이중 Out RST = SynFailed 잉여의 실체 〔측정·파생〕

- **Out RST 히스토그램 완전 정합**: vu400 25×1 + 100×2 + 16×3 = 273 ✓ · vu700 34×1 + 223×2 = 480 ✓ · vu500 99×1 + 97×2 = 293 ✓.
- Out RST 총량(273/480/293) = nstat SyncookiesFailed 버스트(273/480/293) = nstat OutRsts 버스트(273/480/293) — 3채널 완전 일치.
- **드롭(In RST) 대비 잉여** = 이중/삼중 RST 초과분: vu400 273−141=**132**(=100×1+16×2) · vu700 480−257=**223**(=223×1) · vu500 293−196=**97**(=97×1).
- **C12 대조**: C12는 이중 Out RST가 vu500 창에서만 35건 관측됐고 vu300·vu400은 0건이었다. **C13은 드롭이 발생한 3런 전부에서 이중/삼중 RST가 지배적**이다 — 이번 세션에서 두드러진 차이점.
- vu700은 3×RST가 0건이면서 2×RST 223건만으로 잉여 전량이 설명되고, vu400은 1×/2×/3× 세 형태가 혼재한다는 점에서 두 드롭런의 RST 재시도 양상이 서로 다르다.

## 4. SYN 재전송 〔측정〕

- 서버 SYN-ACK 재전송 gap 히스토그램(vu400+vu700 창, n=1,685): **<0.15s 1,008건**(클라 SYN 재전송에 즉응답) · 0.15~0.5s 270건 · **0.9~1.2s(1s) 398건** · 1.9~2.2s(2s) 9건 · 4s 0건. → 1초 배수 백오프 + 즉응답이 혼재하는 패턴(C12와 유사한 backoff 형태).
- 클라 SYN 재전송 플로우 수(§1 표 reSYN≥2 열): vu400 280 · vu700 522 · vu500 418 · vu200 60. 재전송 간격의 정밀 분포는 이번 facts로 별도 산출되지 않았다 — 원인(OS/k6 설정)은 §7 미확정으로 유보.

## 5. 비-k6 트래픽 & nstat 대조 〔측정〕

- 이번 세션은 **매우 깨끗**하다 — 외부 스캐너 IP **0건**, lo0 2패킷(로컬 헬스체크 SYN+SYN-ACK 1쌍)만 존재.
- **Out R.(161) 전량 기동 전 포트닫힘 거절**(17:10:49~17:22:04, 서버 기동 17:21:48 직후 꼬리 4건까지 포함). **런 창 내 Out R. = 0**.
- **기동 전/런 사이 프로브**: 클라 IP가 ~5초 간격으로 단독 SYN 162발(17:10:49~17:30:29) 발생 → 161발은 R.로 거절(기동 전), 1발만 SYN-ACK 응답(기동 직후). 전부 런 창 밖 배경 트래픽이다.
- **C12 대조**: C12는 외부 IP 3종(45.198.224.5, 66.132.172.104/.16)의 스캔성 트래픽과 SynRetrans 램프 +1,950 중 미귀속분이 존재했다. **C13은 이런 외부 트래픽·미귀속 램프가 관측되지 않는다** — 세션 전체 SynRetrans Δ +1,592는 런별 버스트(§3)로 대체로 설명되며, C12 같은 미귀속 이벤트는 없다.

## 7. 관측이 시사하는 것 / 확정하지 않는 것 〔분석 — 사실 아님〕

- 드롭 시퀀스(재전송 SYN에 다른 ISN이 응답되는 ISN₂ 등장 → 첫 ISN 공간에 RST)는 nstat의 쿠키 지문(ReqQFullDoCookies→SyncookiesFailed)과 시각·수량이 동행하며, C12와 동일한 메커니즘으로 보인다. "SYN큐 포화 → 재전송 SYN에 쿠키 SYN-ACK(ISN₂) → 첫 SYN-ACK(ISN₁) 기준으로 완성하려던 핸드셰이크가 쿠키 검증 실패 → RST" 해석과 **모순되는 관측은 없다** — 단 ACK 패킷이 필터에서 빠져 있어(§0) 핸드셰이크 완성 방향은 패킷으로 직접 확인 불가. 확정 아님.
- **드롭 개시 VU가 vu400으로 후퇴한 원인**(C11·C12는 vu300): 실효 SYN큐 한도/클라 볼리/서버 상태 중 무엇인지 이 세션 채널로 특정 불가. vu300이 쿠키를 발동(41)시켰으나 무실패 = 경계 바로 아래라는 사실까지만 확정.
- 클라 SYN 재전송 <150ms 원인(OS/k6 설정)은 이 캡처만으로 특정 불가.
- 이중/삼중 Out RST가 이번 세션 전 드롭런에서 지배적인 이유(서버 부하·재시도 타이밍 등)는 패킷만으로 원인 특정 불가 — 관측된 규칙성(히스토그램 완전 정합)만 사실로 남긴다.
