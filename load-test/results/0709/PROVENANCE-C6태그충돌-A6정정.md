# ⚠️ 태그 충돌 정정 노트 — raw `C6`가 두 번 쓰임 (07-03 비관락 vs 07-09 조건부)

> 로그 분석 에이전트 필독. 이 노트를 안 읽으면 07-03과 07-09를 섞어 오분석함.

## TL;DR

- raw 파일 태그 `C6`가 **서로 다른 두 세션·두 전략**에 중복 사용됨.
  - **07-03** `crew-rush-jian_C6_*_2026-07-03T11-*` = **비관락(PESSIMISTIC) 6차** ← 기존 정본, results/0703/ 아카이브
  - **07-09** `crew-rush-jian_C6_*_2026-07-09T08-*` = **조건부(CONDITIONAL, 원자적 UPDATE) 6차** ← 오늘
- 오늘(07-09) 것은 **A6로 재라벨**한다. 07-03 것은 **C6 그대로 둔다**(비관락 6차가 맞음).
- 구분 기준은 **파일명 timestamp** 및 **mtime 날짜**. `2026-07-09` = A6, `2026-07-03` = C6.

## 전략 확정 근거 (오늘 = 조건부)

- 기동 전략 = **CONDITIONAL(원자적 UPDATE)** — 사용자 직접 확인(07-09).
- 파일 태그가 `C6`로 찍힌 건 러너 태그 실수일 뿐, 전략은 조건부.
- 교차검증 포인트(로그분석 에이전트용): 조건부는 HikariCP `acquire`가 **무사다리(저평탄)**
  지문이어야 함(비관락의 상승 사다리와 대비). Prometheus 회수 후 이 지문으로 재확인 권장.

## 리네임 규칙 (오늘 것만)

- 대상: `results/raw/crew-rush-jian_C6_max10_vu*_2026-07-09T08-*.{summary.json,html}`
  + 오늘 mtime(07-09)인 untimestamped `crew-rush-jian_C6_max10_vu*.json`
- 규칙: `_C6_` → `_A6_` (파일명 치환). 07-03 timestamp/mtime 파일은 **제외**.
- 실행 시점: **스윕 8런 완료 후 배치 리네임**(러너가 남은 런도 C6로 계속 찍기 때문).

## 07-03 데이터 보호

- untimestamped `.json`은 k6 `--out json` **풀 그래뉼러 스트리밍**(vu700 = 3.4MB).
  timestamped `summary.json`(6KB 집계)엔 없는 원본. results/0703/에도 미포함이었음.
- 오늘 스윕이 같은 파일명(`crew-rush-jian_C6_max10_vuXXX.json`)을 **덮어씀**.
- 조치: 07-03 mtime 생존분 6개를 **`results/0703/raw-streaming-backup/`에 백업 완료**
  (vu50·100·200·300·500·700).
- ⚠️ **유실**: 07-03 `vu20.json`·`vu400.json` 그래뉼러는 백업 전 이미 오늘 런이 덮어씀 →
  07-03 vu20/vu400은 **summary.json(집계)만 생존**, granular 소실. (분석은 완료 상태라 영향 경미)

## VU별 매핑 (07-09 조건부 6차 = A6)

셔플 순서: 20, 400, 700, 50, 300, 100, 500, 200

**태그 정정 경위**: vu20·vu400은 러너 태그가 아직 `C6`일 때 실행됨 → `mv`로 `A6` 정정 완료(07-09).
