## 9. 분석 〔분석〕

1. **실험 목적 달성 — 드롭은 락을 따라가지 않고 세션(네트워크)을 따라간다, 최종 확정.** 클라이언트 네트워크를 A1과 맞추자(오히려 더 빠름) **비관락도 vu300부터 40~191건 드롭**됐다. 커널 지문(쿠키 검증 실패→RST, AttemptFails=드롭, ESTAB 결손=드롭, ListenOverflows 0)까지 A1과 완전 동일. 6차(07-03)의 "vu700 무손실"은 비관락의 공이 아니라 **그날 느린 네트워크(RTT 41ms)가 버스트를 11~15초로 펴 준 우연한 백프레셔**였음이 실험으로 증명됐다. 비교문서 §5 판정 적중.

2. **3세션 용량-반응 관계**: RTT 41ms(6차) → 드롭 0 (도착 분산) / RTT 25ms(A1) → vu500부터 드롭 / **RTT 12ms(C7) → vu300부터 드롭**. 네트워크가 빠를수록 버스트가 원형으로 서버에 꽂히고, 드롭 개시 VU가 내려간다. "네트워크가 좋을수록 드롭이 는다"는 역설의 3점 확인.

3. **t3.micro + backlog 256의 실질 천장 재확인**: 원형 버스트 기준 안전선은 **VU ≈ 256(backlog) 부근**. vu200까지는 쿠키조차 발동하지 않고(큐 내 수용), 그 위부터 쿠키 폴백→확률적 검증 실패층에 진입한다. 천장을 올리는 직접 레버는 여전히 accept-count(=listen backlog) 상향.

4. **C7이 A1보다 드롭이 일찍·많이 난 이유 (추정)**: 기저 RTT가 절반이라 버스트 집중도가 더 높았고, SynRetrans·쿠키 재발급 증폭(vu700 발급 919 > VU)이 보여주듯 핸드셰이크 볼리의 유실·재전송 교란도 더 심했다. 전략 차이로 해석할 근거는 없다(드롭 커넥션은 앱 미도달 — A1 날 앱 로그로 증명된 구조).

5. **전략 신호는 드롭이 아니라 p95에 있다**: 무드롭 구간(vu20~200) 완료 p95에서 **A1이 전 구간 300~330ms가량 우세** (C7의 RTT가 유리했는데도). 성공(201) p95도 워밍업 제외 시 A1 우세(161~190 vs 296~388). 비관락의 행 락 직렬화(409도 락 대기 후 반환) 비용으로 해석 가능 — 규약(완료 p95 + 정합성)상 **조건부 UPDATE 우세** 방향. 단 §9.6 캐비앗 하에서.

6. **캐비앗**: (a) C7 서버가 실제 PESSIMISTIC으로 재기동됐다는 파일 증빙 없음(👤 — 다만 p95 열세 패턴이 전략 변경과 정합적. **단, `process_start_time_seconds` 대조로 "A1↔C7 사이 프로세스 재기동 자체"는 직접 확정됨 — `0704_프로메테우스-실측-C7.md` §1. lock-strategy 플래그 값만 여전히 미확정**), (b) C7 vu20은 첫 런 워밍업 오염, (c) 앱 로그 부재로 CR002 대조 미수행(**join_success/join_full은 Prometheus 원시 diff로 부분 해소 — §7 참고**), (d) RTT가 A1과 2배 차이라 "같은 네트워크"가 아니라 "같은 방향으로 더 극단"인 조건임 — 드롭 판정에는 오히려 보수적(비관락에 불리하지 않은 방향). (e) vu400 완료 p95(1,643.9)가 이웃 VU보다 국소적으로 높은 이상치는 이 JVM 생애 첫 Major GC(169ms STW)가 vu400 창에 낀 것이 원인 후보 — `0704_프로메테우스-실측-C7.md` §3.

7. **판정**: 정합성 8런 만점(비관락 무결). 드롭 FAIL 4런은 전략 무관의 수립층 현상. **이 시리즈의 "락 전략별 드롭 비교"는 오늘부로 종결 — 드롭은 비교 지표에서 제외하는 것이 맞다** (판정 기준을 checks/드롭이 아닌 완료 p95+정합성으로 재정의한 기존 결정의 재확인).
